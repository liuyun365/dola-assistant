# 豆啦啦辅助（dola-assistant）

豆啦啦（Dola）本地自动化工具集：把 AI 视频工作流的**提示词 + 资产图**一键推送到豆啦啦实例对话框，默认只填框、不自动发送。

纯 Python 标准库实现，**零第三方依赖**，全部本地运行（不上传任何数据）。

## 模块组成

| 模块 | 端口 | 说明 |
|---|---|---|
| `dola_connector/` | — | **稳定契约层**：豆啦啦本地 API（`127.0.0.1:17823`）的封装。实例管理、填文本、贴图、发送。上层模块只调它，不自己拼 URL |
| `prompt_manager/` | 8899 | **提示词工作台**（Web GUI）：文档树 → 分镜解析 → 资产匹配 → 就地编辑保存 → 推送。主力工具 |
| `prompt_pusher/` | — | 命令行推送工具（早期版本，保留备用） |

## 环境要求

- Windows + **豆啦啦无印浏览器**（需保持运行，其内置 Automation 服务监听 `127.0.0.1:17823`，无需 token）
- Python 3.10+（任意发行版，无需 `pip install`）

## 快速开始

```bat
双击 run_prompt_manager.bat
```

自动打开 <http://127.0.0.1:8899/>。或手动：

```bash
python -m prompt_manager.server
```

## 使用流程

1. **连豆啦啦**：先打开豆啦啦客户端并登录至少一个实例；工作台顶栏选默认实例（连不上时点「重试连接」）。
2. **加文档**：左栏「+ 添加文件夹 / + 添加文件」→ 可视化选择器逐级进入（记忆上次目录，可回退到盘符列表）。
3. **自动分镜**：中点开提示词文档，自动切分为分镜卡片。
4. **配资产**：右栏「导入图片 / 导入文件夹」（递归收集子目录）→ 匹配区按资产名预匹配图片，可手动改 →「提交匹配」。
5. **推送**：每个分镜点「推送」（文本+资产填入该分镜所选实例），或顶栏「推送全部」（按各分镜实例轮询）；勾选「推送后自动发送」则每填一个即生成。

## 分镜拆分规则（已按多剧集格式校准）

| 规则 | 说明 |
|---|---|
| 顶层分镜边界 | `### 镜头N｜00–30s｜标题`（Markdown 标题）；也支持 `第N镜/集/场`、`镜头N：`、`分镜N`、`场景N`、数字序号、`---` 分隔线 |
| 时间轴子片段不拆 | 镜头块内 `**时间轴细分：**` 下的 `分镜01-01：…`（连字符编号 N-NN）是 30s 成片内部片段，**不**作为分镜边界；但站位文件的 Markdown 标题 `### 分镜01-01｜…` 仍正常切分 |
| 文档总览过滤 | 「拆分结果 / 源文件: / X.X原时长 / 按X.X规则拆分 / 共约N秒 / 拆分为N个镜头」等章节规划段自动剔除 |
| 说明行过滤 | 文件首行「全文使用seedance2.5生成」等无分镜内容的说明段不生成空白卡片 |

## 资产识别规则（人物 + 场景 + 物品，物品可无）

- **唯一来源是显式资产声明**：
  - `图N` 标记：`图一：沈清辞` / `图一为沈清辞` / `图一＝陈母（身高162cm）` / `图五是客厅` / `图一对应F02 人物设定/女主_小三形象_v1.png`
  - `场景映射：客厅`、`物品映射：婚纱、戒指`（无图N 的裸名，按 `，,；;、` 拆分；括号内是环境描述，不拆）
- **清洗**：去身高/年龄/括号/结尾修饰词，只留纯名字（`陈母（身高162cm）` → `陈母`）
- **黑名单**：`无 / 暂无 / 无独立参考图` 等占位词不当资产
- **按图号去重**：同一图号在「参考对应」「角色映射」多行重复只取一次；排序 = 人物（按图序）→ 场景 → 物品
- **匹配**：文件名 + 各级父目录名 + `_`/`-` 拆词做候选键（`角色/沈清辞/正面.png` 可靠父目录命中），包含关系 + difflib 兜底；整篇无任何显式资产声明时（如站位文件）才用资产库类别词兜底

## 就地编辑与保存

- 每个分镜点「编辑」→ 正文可直接改；**一边改一边生效**（推送即用最新文本）
- 「保存」按钮或编辑中 **Ctrl+S** → 写回原文件
- 保存采用**原位替换**：只覆盖该分镜自身字符区间，文件其余部分原样保留；**首次保存前自动生成 `<文件>.bak` 原件备份**
- 有未保存修改时，切换文件 / 重新匹配 / 关闭页面都会拦截确认；标题旁红色 ● 提示未保存

## 推送语义（重要）

豆啦啦**每个实例只有一个输入框**：

- **单分镜推送**：填入该分镜头部下拉所选实例（未选则跟随顶栏全局实例）
- **推送全部**：按各分镜的实例下拉轮询分配；多个分镜落同一实例且未开「自动发送」时，后一个会覆盖前一个——此时应开启自动发送，或把分镜分散到不同实例
- 默认**只填不发送**，生成按钮由用户在豆啦啦里自己点

## API 一览（prompt_manager，127.0.0.1:8899）

| 方法 | 端点 | 说明 |
|---|---|---|
| GET | `/api/version` | 服务版本（改代码后核对是否生效） |
| GET | `/api/file?path=` | 解析文件：分镜（含起止区间）、资产名、预匹配 |
| POST | `/api/file/save` | `{path,index,text}` 分镜文本原位写回（自动 .bak） |
| GET/POST/DELETE | `/api/roots` | 文档树根目录管理 |
| GET | `/api/list` `/api/drives` | 目录列表 / 盘符（可视化选择器） |
| GET/POST/DELETE | `/api/assets` | 资产库（导入递归收集、单删、清空） |
| GET | `/api/asset?path=` | 资产图片二进制 |
| POST | `/api/match` | 保存「资产名 → 图片」映射（`<提示词>.match.json`） |
| GET | `/api/instances` | 豆啦啦实例列表 |
| POST | `/api/push` | `{instance,text,assets,send}` 推送到实例 |
| GET | `/api/shutdown` | 受控退出服务（启动器用它停旧实例，**严禁 taskkill**） |

## 开发注意事项（踩坑记录）

1. **`.bat` 必须纯 ASCII + CRLF + 无 BOM**：cmd 默认 GBK 解码，文件里写中文会乱码崩窗（`.py` 内中文无碍）。
2. **严禁 `taskkill` 杀 PID**：netstat 解析异常时可能取到系统进程 PID，强杀会触发 Windows 重启。停旧服务一律用 `GET /api/shutdown`（受控退出）。
3. **类方法内严禁 `import os`**：函数内一旦 import，整个函数内 `os` 都变局部变量，其他分支引用即 `UnboundLocalError`。一律用模块顶部全局导入。
4. **后端改动需重启启动器**（关黑窗重双击 bat），**前端改动浏览器 Ctrl+F5** 即可；黑窗首行/页角版本号（`SERVER_VERSION`）用于确认新代码生效。
5. 服务有自愈循环：单请求异常写 `state/server.log` 并自动重启，不会整个退出。
