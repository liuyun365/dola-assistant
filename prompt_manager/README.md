# 提示词工作台（prompt_manager）

一个**本地运行**的提示词工作台，把提示词文档与资产图组织起来，并通过 `dola_connector` 一键推送到豆啦啦（Dola）实例的对话框。

界面仿资源管理器，三栏布局：

- **左 · 文档区**：资源管理器式树状浏览本地文件夹/文件。顶栏「+ 添加文件夹 / + 添加文件」会弹出**可视化选择器**——可进入各盘（C:/D:/E:…）、桌面/文档/下载/图片快捷入口，逐级展开文件夹，选中后确认即可；删除只删记录不删实体。
- **中 · 提示词正文**：点开左侧文档即在中间展开，自动识别分镜（支持 `镜头N` / `分镜N` / `场景N` / `第N镜` / `数字序号` / `### 标题` 等写法，以及 `---` 分隔线）。识别到的文档级标题（如 `# 第一集 分镜`）会自动并入首个分镜，不会生成空白卡片。每个分镜头部有「复制」（复制整段）与「推送」按钮，以及该分镜专属的**实例下拉**（默认跟随顶栏全局实例）；正文可点「编辑」就地修改。
- **右 · 资产库 + 资产匹配**：
  - 上方资产库：「导入图片 / 导入文件夹」打开可视化选择器，可勾选多张图片或选整个目录。导入后以**缩略图网格**展示（图多自动滚动），`×` 移除。
  - 下方资产匹配：**以资产名 → 图片为中心**。左列列出从提示词中识别到的资产名（如 `沈清辞`、`街道`、`客厅`），右列下拉选择对应图片（已按文件名**预先模糊匹配**，可手动改）。点「提交匹配」保存——之后每个分镜会按自身引用展开为「完整」的图片集。同一资产名若在多个分镜出现，匹配界面只出现一次，但每个分镜都拿到完整图片。

## 与豆啦啦的对接

本模块**不直接**与豆啦啦通信，只调用稳定的 `dola_connector`（见同级 `dola_connector/`）。推送逻辑：先 `ensure_instance(实例)` 切到目标实例，再 `paste_text(分镜文本)` + `paste_images(资产路径)`，默认**只填框不发送**（顶栏可勾「推送后自动发送」）。

## 「推送全部」与实例的对应关系（重要）

豆啦啦**每个实例只有一个输入框**。因此：

- **单分镜「推送」**：用该分镜头部下拉所选的实例（未单独选则跟随顶栏全局实例），把文本+资产填入该实例输入框，由你手动点「生成」。
- **「推送全部」**：按**每个分镜各自的实例下拉**依次推送。
  - 若各分镜分到**不同实例** → 各实例分别收到对应分镜，互不干扰（推荐做法：把不同分镜指定到 Dola-32 / Dola-33 等不同实例）。
  - 若多个分镜**落到同一实例**且未勾「自动发送」→ 后一个会覆盖前一个输入框内容，**只有最后一个留在框里**。此时应开启「自动发送」（每填一个就生成一次），或把分镜分散到不同实例。

## 使用

1. 双击 `..\run_prompt_manager.bat`（或 `python -m prompt_manager.server`），自动打开 `http://127.0.0.1:8899/`。
2. 顶栏选好默认豆啦啦实例（Dola-32 / Dola-33 …）；如需逐分镜指定，可在中间分镜卡片的实例下拉中单独改。
3. 左栏用可视化选择器加入提示词所在的文件夹/文件 → 中点开文档 → 自动分镜。
4. 右栏导入资产图 → 资产匹配区会自动列出资产名并预匹配图片，手动微调后「提交匹配」。
5. 每个分镜点「复制」复制文本，或点「推送」把文本+资产填入豆啦啦；顶栏「推送全部」可按各分镜实例依次推送。

## 目录结构

```
prompt_manager/
├─ server.py        # 标准库 http.server 后端：REST API + 托管前端
├─ parser.py        # 分镜解析 + 资产引用提取
├─ matchers.py      # 资产名->图 的模糊预匹配与按分镜展开
├─ web/
│  ├─ index.html    # 三栏单页 + 可视化选择器弹窗
│  ├─ app.js        # 前端逻辑
│  └─ style.css
└─ state/           # 运行时持久化（已添加目录、资产库、匹配结果）——不入库
```

## 说明

- 仅用 Python 标准库，无需 `pip install` 任何包。
- 资产匹配文件保存在提示词文件同名的 `<提示词>.match.json`（记录「资产名 → 图片」），可重开复用。
- 「添加文件夹/文件」「导入图片/文件夹」均通过**可视化选择器**完成（不要求手输路径）。
- 服务器端口默认 `8899`，如需修改见 `server.py` 的 `DEFAULT_PORT`。
